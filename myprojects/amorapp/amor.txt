## 4. Full Description (case-study page)

**AMOR** is a mobile AI companion app for iOS and Android. The idea is simple: instead of typing at
a chatbot, you can **call** it — tap once and have a natural, hands-free conversation, the way you'd
talk to a friend on the phone.

I built the product end to end: the React Native front end, the Supabase backend and database
schema, the server-side voice pipeline, the authentication and guest system, and the Stripe
payment and wallet layer.

**What makes it interesting technically.**
The hard part of a voice app isn't the AI — it's making the conversation *feel* natural. Most voice
apps make you hold a button while you speak. AMOR doesn't. I implemented a custom **Voice Activity
Detection (VAD)** system that continuously reads the microphone's audio level and works out on its
own when you've started speaking and when you've finished. It waits out short pauses, rejects
background noise, and ends the recording precisely when you stop — so the call loop is completely
hands-free: *you speak → it detects silence → it thinks → it replies → it listens again.*

**Cost and security.**
API keys can't live inside a mobile app, and voice is expensive to run. So the entire AI pipeline —
speech-to-text, LLM, text-to-speech — runs server-side inside a Supabase Edge Function. The app only
ever sends audio and receives audio; no provider key ever touches the device. The same principle
applies to money: Stripe's secret key lives only in an edge function, wallet balances are computed
in the database through `SECURITY DEFINER` functions, and top-ups are credited only after the
payment is re-verified against Stripe — with idempotency, so a replayed request can never
double-credit an account.

**The product side.**
Users can try the app instantly as a guest with small daily limits, then create an account — at
which point all their guest conversations and call history are **migrated into the new account** by
a single database function, so nothing is lost. Registered users get a wallet: chat messages cost
1¢ each, voice calls bill at $1.00/hour charged **per second actually used**, topped up with real
Stripe payments.

## 5. Key Features

**Conversation**
- Text chat and hands-free voice calling with the same AI companion
- Seamless switching between chat mode and call mode mid-conversation
- Guided "first call" onboarding script that introduces the companion and learns the user's name
- Full call history with replayable transcripts

**Voice engine**
- Custom **Voice Activity Detection** — no push-to-talk; the app detects speech start and end from
  live audio metering, with tunable dB threshold, silence duration and minimum-speech guards
- Server-side pipeline: **Whisper** speech-to-text → **GPT-4o-mini** → **OpenAI TTS**
- Audio playback with a per-companion voice

**AI personalities**
- **7 distinct companions** (Luna, Aria, Alex, Marcus, Sienna, Theo, Iris) — each with its own
  system prompt, personality profile, TTS voice, avatar and accent color that re-themes the UI
- Per-companion memory: each companion builds its own long-term context about the user

**Accounts & data**
- Guest mode with device-based sessions — usable in seconds, no signup wall
- Email/password auth via Supabase, with real-time password-strength validation
- Forgot-password and reset flows over an `amor://auth` deep link
- Automatic guest → registered-user data migration (conversations, messages, call history)
- Row Level Security on every table

**Payments**
- Stripe wallet with $4.99 / $9.99 / $19.99 top-up packages
- Per-second billing for voice calls, per-message billing for chat
- Server-verified, idempotent crediting — the Stripe secret key never leaves the backend
- Pricing driven from a `pricing_config` table, so rates change without an app update

**Polish**
- Splash → onboarding carousel → auth gate → main app flow
- Three-tab layout (Chat · Calls · Account) with badges and active states
- Offline-tolerant local persistence via AsyncStorage
- Branded transactional email templates, plus Privacy Policy, Terms and Help screens
- Fully typed in TypeScript throughout

## 8. Challenges & Solutions

**Making voice feel like a real call, not a walkie-talkie.**
Fixed-duration recording either cut people off mid-sentence or left awkward dead air. I wrote a VAD
service that samples the microphone's metering level every 100 ms, requires roughly half a second of
sustained speech before it counts as "the user is talking," then ends the turn after 1.5 s of
silence. The result is a fully hands-free conversation loop with thresholds that can be tuned for
noisy environments.

**Running a paid AI pipeline from an app that can't hold secrets.**
Every AI and payment call moved into Supabase Edge Functions. The client sends audio and gets audio
back; the OpenAI and Stripe keys exist only as server secrets. This also made pricing changes and
model swaps possible without shipping a new app build.

**Letting people try the app without an account, without losing their history.**
Guests get a device-scoped session and small daily limits. The moment they sign up, a single
`migrate_guest_to_user()` database function re-parents every conversation, message and call record
to the new user ID — designed to be safe to run more than once.

**Billing accurately for something measured in seconds.**
Wallet balance and every deduction live in Postgres behind `SECURITY DEFINER` RPCs, so the client
can never write its own balance. Calls bill per second at an hourly rate read from a config table,
and top-ups are credited only after the PaymentIntent is re-fetched from Stripe and verified for
status, amount and owner — keyed by payment ID, so replays are harmless.
